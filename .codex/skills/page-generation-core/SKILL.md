# 页面生成通用流程

把页面生成里的通用动作收口到这个 skill：确认、沟通、交付。

## 核心规则

- 只要用户请求生成页面，就先做一次二次确认，再进入页面生成。
- 二次确认要友好、简洁、聚焦，让用户容易直接回答。
- 不要对用户说内部执行细节，例如可写环境、落盘权限、工作区限制、先写项目文件再处理等话术。
- 如果业务 skill 已经能从文档中判断页面能力不存在，就直接反馈不支持，不要继续兜圈子。
- 如果只是部分字段缺失，就明确说明这些字段未找到并在页面中省略，不要因此退回静态页。

## 二次确认方式

二次确认只问“当前页面真正还存在分歧”的内容，不重复问没有歧义的项。

优先确认：

- 页面具体是哪一个模块或场景
- 用户要覆盖全部子场景，还是只做其中一种
- 是否需要 SSE
- 需要展示哪些字段

问题数量尽量控制在一轮内解决。

## 用户沟通风格

- 先简短说明已理解到的范围。
- 再提出 1 到 3 个最关键的收敛问题。
- 如果有明显可选项，优先给出选项式确认。
- 问题必须是用户能立即回答、且会影响页面范围的问题。

## 正式页面交付规则

- 首版页面就要是正式页面，不要先给静态演示页。
- 正式页面默认输出为完整单文件 HTML，除非用户明确要求拆分。
- 如果业务 skill 已经给出可调用契约，页面必须接上真实接口。
- 若有省略字段，在最终回答里明确列出“未展示字段清单”。

## 最终回答结构

优先采用以下结构：

1. 一次友好的二次确认，或用户确认后的简短摘要
2. 简要的 API / SSE 映射
3. 若有省略字段，列出“未在文档中找到，因此未展示”的字段清单
4. 只有确认完成且能力受支持时，输出完整 `html` 代码块
