# Workbench Layout Prompt Template v2

用于把自然语言页面需求改写成可执行的结构化 prompt，并强制锚定本地参考页。

## 使用规则

生成前先明确：

- 壳层参考页
- 主参考页
- 辅助参考页（0 到 2 个）
- 页面名称
- 页面类型
- 业务模块
- 页面目标
- 主要区域
- 关键字段
- 关键交互
- 必要状态

如用户未给足信息，优先做保守推断。

## 页面类型推荐映射

| 页面类型     | 主参考页                           |
| -------- | ------------------------------ |
| 工作台模块首页  | `shell-workbench.html`         |
| 表格列表页    | `page-table-standard.html`     |
| 行情联动页    | `page-market-standard.html`    |
| 审批/录入页   | `page-operation-standard.html` |
| 策略监控页    | `page-strategy-standard.html`  |
| 设置页      | `page-settings-standard.html`  |
| 弹窗/二次确认  | `page-dialog-standard.html`    |
| 消息/告警中心  | `page-message-standard.html`   |
| 白名单维护页   | `page-whitelist-standard.html` |
| 审批详情页    | `page-approval-standard.html`  |
| 行情看板页    | `page-board-standard.html`     |
| 交易前风控校验页 | `trade-risk-precheck.html`     |

## 硬约束模板

```text
请基于以下本地参考文件生成一个新的桌面交易客户端 HTML 原型页面。

生成前请先读取并理解以下文件：
- `[壳层参考页，如适用则填 shell-workbench.html]`
- `[主参考页，必填且只能 1 个]`
- `[辅助参考页 1，如无可省略]`
- `[辅助参考页 2，如无可省略]`
- `assets/tokens.css`
- `assets/app.css`
- `assets/components.css`

这些文件是唯一的视觉与交互参考源。不要改造成通用 SaaS 后台，不要发明脱离参考页的新设计体系。

页面信息：
- 页面名称：[填写]
- 页面类型：[填写]
- 业务模块：[填写]
- 页面定位：[填写]

页面目标：
- [目标 1]
- [目标 2]
- [目标 3]

主要区域：
- [区域 1]
- [区域 2]
- [区域 3]
- [区域 4]

关键字段：
- [字段 1]
- [字段 2]
- [字段 3]
- [字段 4]

必须覆盖的状态：
- [状态 1]
- [状态 2]
- [状态 3]

关键交互：
- [交互 1]
- [交互 2]
- [交互 3]
- [交互 4]

硬要求：
1. 最终只输出完整的单文件 HTML，不要输出解释说明。
2. HTML 必须可直接在浏览器本地打开运行。
3. CSS 和 JS 必须内嵌在同一个 HTML 文件中。
4. 页面必须保持深色、高密度、表格优先、工具栏优先的桌面交易客户端风格。
5. 页面必须是一屏工作台布局；外层避免整页长滚动，密集区域使用内部滚动。
6. 页面必须包含真实可演示交互，至少覆盖表格行选中、筛选/联动、标签切换、弹窗开关、状态切换。
7. 页面必须至少包含三种状态表现，优先从正常、空态、加载、异常、只读、无权限、断连中选择。
8. 页面文案和字段命名必须贴近真实交易客户端，不要使用泛化演示字段。
9. Bid / Ofr、运行中 / 暂停 / 停止、预警 / 拦截等状态语义和颜色不要随意改动。
10. 如参考页中存在顶部工具栏、主表格区、右侧快捷区、状态区等结构，应优先保留这些结构语言。
```
