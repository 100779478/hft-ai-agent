# HTML 成品交付

把最终页面生成结果格式化成便于机器解析和人工查看的输出。

## 必要格式

优先采用以下结构：

1. 简短摘要
2. API / SSE 映射
3. 若有省略字段，列出“未在接口文档中找到，因此未展示”的字段清单
4. 若页面不支持，直接说明，不输出 HTML
5. 只有接口文档支持时，输出一个完整的 `html` 代码块

## 交付规则

- 默认输出为单个自包含 HTML 文件。
- 必须包含 `<!doctype html>`。
- CSS 和 JavaScript 默认内联。
- 首版页面就要真实调用接口，不要输出静态演示页。
- 接口没有的字段无需展示，但要明确告知用户哪些字段被省略。
- 页面布局默认优先一屏展示，超出内容通过内部滚动区域承载。

## 先决条件

在输出 HTML 之前，先确认：

- 页面能力能在 `HFT-SDK-接口文档.md` 中找到依据
- 页面要求的字段已完成文档检索
- 若有未找到字段，已整理成省略字段清单

如果页面能力不满足上述条件，不要输出正式 HTML。

## 强制检查

输出前必须逐项检查：

- HTML 中存在真实 `fetch` 调用
- 如果需要 SSE，存在真实 `EventSource` 逻辑
- 页面主数据区由真实响应驱动渲染
- 存在 loading、error、empty 状态处理
- 未使用硬编码业务数据作为主数据源
- 已省略文档中没有的字段，且对用户有明确说明
- 页面外层没有无限纵向拉长；如果内容超出，使用内部滚动条

## 最低实现要求

最终 HTML 至少应包含：

- base URL 常量
- 请求参数收集函数
- 真实请求函数
- 响应解析与错误处理函数
- 真实渲染函数
- 如有 SSE，则包含连接、消息处理、断开逻辑
- 事件绑定代码
- 一屏布局容器与内部滚动区域的样式约束
