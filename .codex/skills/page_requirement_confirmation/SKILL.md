# 页面需求确认

只要用户想要一个页面或界面，都先做一次基于接口文档的二次确认，然后再进入页面生成。

## 首要规则

- 不要先生成静态页面给用户看。
- 确认问题必须基于接口文档来问。
- 无论需求是否已经看起来足够明确，都要先确认一次页面范围。
- 不要对用户说可写环境、落盘权限、工作区限制这类内部话术。

## 需要确认的内容

1. 页面名称或模块
   页面名本身是什么，例如“双边报单面”；它能否在接口文档中检索到？
2. 具体场景
   同类能力下，用户要哪一种文档中已有场景？
3. 核心动作
   要调用哪些接口动作？
4. 展示字段
   需要展示哪些字段？其中哪些字段在接口文档中可检索到？
5. 数据方式
   需要 HTTP、SSE，还是两者都需要？
6. 输出要求
   默认输出首版即可真实调用接口、且优先一屏展示的 HTML 页面。

## 典型确认示例

- 用户说“报单页面”时，应确认：
  是全部报单，还是只生成 FAK 场景报单，还是双边报单等文档中已有页面能力。
- 用户说“行情页面”时，应确认：
  是哪一种行情，例如内盘行情、broker best quote、broker deal、market status 等文档中已有模块。

## 反馈规则

- 页面能力不在接口文档中：直接说明当前系统不支持。
- 字段不在接口文档中：明确告知该字段未找到，并在页面中省略。
- 不要因为缺少部分字段就退回静态页；只要页面能力成立，就生成支持字段范围内的真实页面。
