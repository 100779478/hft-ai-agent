# 需求补全

通过简短、聚焦的问题做一次二次确认，但所有确认都要基于接口文档。

## 必做规则

- 只要用户请求页面，就先做一次二次确认，再生成页面。
- 即使接口文档已经足够，也要确认一次页面范围和场景归属。
- 不要先给静态页再让用户确认。
- 不要对用户暴露内部执行细节，例如可写环境、落盘权限、工作区限制等。

## 优先确认项

1. 页面名称或模块
   页面名本身是什么，例如“双边报单面”；它能否在接口文档中检索到？
2. 具体场景归属
   如果同类能力在文档中有多个场景，用户要哪一个？
3. 核心动作
   需要支持哪些真实接口动作：查询、提交、撤销、订阅？
4. 展示字段
   用户要求展示哪些字段，这些字段是否都能在接口文档中找到？
5. 数据方式
   是 HTTP、SSE，还是两者都需要？

## 确认方式

- 只确认接口文档相关信息，不做脱离文档的泛化确认。
- 问题数量尽量少，但要能让页面范围收敛。
- 提问语气要友好自然，让用户容易直接选择。
- 如果页面能力在文档中不存在，直接说明当前系统不支持。
- 如果字段不存在，明确告知该字段未找到并在页面中省略。

## 场景示例

- 用户说“报单页面”时，要确认：
  是全部报单能力，还是只做 FAK 报单、双边报单等文档中已有场景。
- 用户说“行情页面”时，要确认：
  是哪一种文档中已有行情模块，例如内盘行情、broker best quote、broker deal、market status 等。

## 何时停止并反馈

- 页面能力检索不到：直接反馈“当前系统不支持”
- 字段检索不到：反馈“该字段未在接口文档中找到，将不在页面中展示”
