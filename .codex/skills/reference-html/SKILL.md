# HFT 标准页面参考包 Prompt 模板

## 1. 使用目标

这份模板给产品经理或设计同学在做 vibe coding 时直接使用，目的是让模型生成的新页面尽量贴近现有客户端，而不是漂移成通用网页后台。

## 2. 固定总规则

无论生成什么页面，都建议把以下约束原样带上：

```text
请严格参考我提供的标准 HTML 页面，生成新的业务页面。

总要求：
1. 保持桌面交易客户端风格，不要改成通用网页后台、移动端界面或卡片流首页。
2. 保持高密度、深色主题、表格优先、工具条优先、状态信息明确的设计语言。
3. 保持现有客户端常见结构：顶部状态/标题区、紧凑筛选条、主表格区、辅助详情区或右侧操作区。
4. 控件尺寸、边距、圆角、按钮高度、输入框高度尽量继承参考页。
5. 必须保留加载态、空态、只读态、无权限态、断连态中的至少一种。
6. 可以替换业务字段和文案，但不要重构页面骨架和交互密度。
7. Bid / Ofr、运行中 / 暂停 / 停止 / 风控等状态颜色语义不要随意改动。
8. 如果页面属于工作台子页，不要设计成营销式首屏，不要做大面积留白。
9. 只要页面存在滚动容器，就统一定制深色主题滚动条；宽度默认按 `6px` 实现，不要保留系统默认的厚滚动条。
```

## 3. 标准提示词母版

```text
请基于以下参考页生成一个新的 HFT 客户端业务页面：

参考页：
- 壳层参考：`shell-workbench.html`
- 主页面参考：`[在这里填标准页文件名]`
- 如涉及弹窗：`page-dialog-standard.html`
- 如涉及消息：`page-message-standard.html`
- 如涉及设置：`page-settings-standard.html`

目标页面：
- 页面名称：[填写页面名称]
- 业务模块：[CFETS / SSE / FIX / Futures / Strategy / Shared]
- 页面角色：[主业务页 / 查询页 / 操作页 / 配置页 / 弹窗]

页面目标：
[用 3 到 6 条说明这个页面要完成什么]

必须包含的区域：
1. [区域一]
2. [区域二]
3. [区域三]
4. [区域四]

必须展示的状态：
- [例如：运行中、已暂停、风控拦截、只读、空态]

生成要求：
1. 输出完整 HTML。
2. 样式尽量继承参考页结构和视觉语言。
3. 页面信息密度偏高，优先使用表格、工具条、紧凑表单。
4. 不要引入新的设计体系，不要改成浅色、圆润卡片风。
5. 用占位业务数据即可，但字段命名要像真实交易客户端。
```

## 4. 常用场景模板

### 4.1 新建一个“表格型业务页”

适用：

- 成交查询
- 持仓明细
- 风控列表
- 规则列表

```text
请参考 `shell-workbench.html` 和 `page-table-standard.html`，生成一个新的高密度表格业务页。

目标页面名称：[页面名]
用途：[例如：展示某类策略成交明细]

要求：
1. 页面顶部保留紧凑筛选条。
2. 主体区域以表格为主，表格列数保持在 8 到 12 列的典型密度。
3. 保留批量操作按钮、导入导出或查询按钮中的一部分。
4. 右侧可以有简短详情摘要，但不要做成完整详情页。
5. 至少包含一行选中态、一行正常态、一行异常态。
6. 页面必须像桌面交易客户端，不像普通 BI 看板。
```

### 4.2 新建一个“行情联动页”

适用：

- 综合最优行情
- 深度行情
- 逐笔成交
- 行情联动下单页

```text
请参考 `shell-workbench.html` 和 `page-market-standard.html`，生成一个新的行情联动页面。

目标页面名称：[页面名]
用途：[例如：展示交易所信用债综合行情并支持快速联动下单]

要求：
1. 页面要同时体现行情查看和交易承接能力。
2. 保留综合行情表、深度梯队或逐笔成交中的至少两种结构。
3. 保留 Bid / Ofr 颜色语义。
4. 页面右侧或下方必须有一个快速交易承接区域。
5. 不要把页面设计成纯看板或纯表单。
```

### 4.3 新建一个“审批/录入页”

适用：

- 审批单
- 白名单录入
- 风控参数维护
- 手工成交录入

```text
请参考 `page-operation-standard.html` 和 `page-dialog-standard.html`，生成一个新的录入审批页面。

目标页面名称：[页面名]
用途：[例如：录入并提交某类审批申请]

要求：
1. 页面由录入区 + 待处理列表区组成。
2. 录入区使用紧凑双列或三列表单。
3. 列表区使用高密度表格。
4. 页面中需要有校验反馈区。
5. 主按钮只允许一个，例如“提交审批”或“保存”。
```

### 4.4 新建一个“策略监控页”

适用：

- 策略组管理
- 策略实例监控
- 指标页
- 日志页

```text
请参考 `page-strategy-standard.html`，生成一个新的策略监控页面。

目标页面名称：[页面名]
用途：[例如：展示某策略模板下所有实例的运行状态]

要求：
1. 页面必须突出状态、批量操作、实例表格。
2. 保留运行中、暂停、停止、风控拦截等状态表现。
3. 保留工具条中的启动、暂停、停止、导入、导出等操作语言。
4. 页面右侧或下方保留实例摘要或参数摘要。
5. 不要把页面做成纯图表大屏。
```

### 4.5 新建一个“设置页”

适用：

- 全局设置
- 默认参数页
- 提醒设置
- 账户配置

```text
请参考 `page-settings-standard.html`，生成一个新的设置页面。

目标页面名称：[页面名]
用途：[例如：维护交易偏好和提醒规则]

要求：
1. 左侧保留稳定的设置导航。
2. 右侧为紧凑配置表单，不做大段说明文案。
3. 顶部保留保存/取消动作。
4. 输入框、下拉框、表单分组高度和间距继承参考页。
5. 页面整体仍属于桌面工作台的一部分。
```

## 6. 生成后检查清单

把模型生成结果拿回来后，可以快速用下面的清单检查：

- 是否还是深色高密度桌面风格
- 是否还有顶部工具条和明确状态区
- 是否保留表格优先而不是卡片优先
- 是否保留操作按钮语言而不是只剩浏览
- 是否保留风险、运行、消息等状态语义
- 是否存在至少一个真实业务态和一个异常态
- 是否避免了过大的间距、过圆的卡片、过浅的配色

## 7. 不建议出现的偏移

以下风格偏移需要明确避免：

- 改成浅色 SaaS 后台风
- 改成大量卡片和统计数字的大屏风
- 改成移动端表单风
- 去掉右侧快捷操作或工具条
- 去掉多状态表达，只保留“正常页面”
- 把高频交易页做成解释性很强但不利于操作的页面

## 8. 最短可用模板

如果时间很紧，可以直接复制下面这段：

```text
请参考 `shell-workbench.html` 和 `[标准页文件名]`，生成一个新的 HFT 客户端业务页面。

要求：
1. 保持桌面交易客户端风格，深色、高密度、表格优先。
2. 保持顶部工具条、状态表达、紧凑筛选区和主工作区结构。
3. 控件高度、边距、按钮风格、状态标签风格继承参考页。
4. 不要改成通用网页后台，不要做大卡片和大留白。
5. 页面必须包含至少一种异常或边界状态。

目标页面：
[在这里描述页面名称、用途、字段和关键动作]
```
