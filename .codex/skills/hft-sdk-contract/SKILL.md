# HFT SDK 契约映射

本项目中的页面生成默认使用这个 skill。

## 阅读顺序

1. 读取 [HFT-SDK-接口文档.md](/D:/hft-ai-agent/HFT-SDK-接口文档.md)。
2. 读取 [hft-sdk-view.md](/D:/hft-ai-agent/.codex/skills/hft-sdk-contract/references/hft-sdk-view.md) 作为精简摘要。
3. 先检索用户要求的页面名、模块名、动作名和字段名。
4. 只抽取与当前页面请求直接相关、且能在文档中找到依据的接口。

## 需要提取的内容

对于每个选中的接口，至少提取：

- path
- method
- 请求对象名称
- 请求字段
- 默认值
- 响应结构
- 应显示在表格、详情区、状态标签或摘要区的响应字段
- 相关 SSE 事件名称
- 前端应如何组装请求
- 前端收到响应后应如何更新 DOM

此外，还要记录：

- 用户要求但文档中未找到的字段
- 用户要求但文档中未找到的页面模块或页面名称

## 映射规则

- 不要发明接口文档中不存在的端点。
- 不要发明无法从文档追溯的业务字段、表格列、筛选项或操作。
- 字段不在文档中时，不展示该字段，并明确告知用户该字段未在接口文档中找到。
- 文档中给出的默认值，应优先作为 HTML 表单默认值。
- 页面结构应由接口契约反推。
- 前端实现必须由契约反推真实调用函数，例如查询函数、提交函数、订阅函数、断开函数、渲染函数。
- 首版页面就要落成真实调用，不要先生成静态原型页。
- 页面名本身也必须可追溯；例如用户要求“双边报单面”，只有在文档中能检索到对应依据时，才允许继续生成。
- 如果整个页面能力不在文档中，应直接标记为“当前系统不支持”。

## 输出契约格式

输出给下游生成步骤时，至少包含：

- HTTP 基础地址
- SSE 地址模式
- 已选择接口
- 这些接口推导出的页面区域
- 字段默认值
- 响应结构
- 展示字段
- 省略字段清单
- 事件订阅
- 页面里的真实函数映射
  例如：哪个按钮触发哪个请求，哪个响应填充哪张表，哪个事件更新哪个面板
- 不支持项清单

## 首版实现要求

输出给下游时，必须让页面生成步骤清楚以下内容：

- 如何从表单值组装请求 body 或 query 参数
- 调用成功后，响应中的哪部分数据进入哪块 UI
- 调用失败后，错误如何展示
- 如果有 SSE，如何建立连接、消费消息、更新界面和关闭连接
- 哪些字段因为文档未提供而不展示
- 如果整个页面需求无法检索到对应能力，应直接停止并标记为“当前系统不支持”
